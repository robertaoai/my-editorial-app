### 3.4 Evaluation methods — fixed before any result (`D-270`, for `SV2-DOR-05`)

**Loader (`SV2-U02`) — natural sentinels.** For each in-scope file, choose an existing, unique line at its start,
middle and end; pin each by line number and SHA-256 at the read commit. **No rule file is edited** (`D-266` item 2).
The agent under test quotes each sentinel; a missing or altered quote means that region is not visible. Each run
records: tool, version and backend; the loaded-file inventory; the three quotes per file; byte and character counts;
`/context` tokens where shown. It classifies the result as **complete loading**, **discovery failure**, **per-file
truncation** or **total-context truncation**, and records **duplicated text** when one sentinel is quoted from two
sources (for example `AGENTS.md` loaded both natively and by import).

**Falsifiability controls (`D-271`, from `B-139` at `0a70c1a`).** A correct quotation alone does not prove which loader
supplied a line, and a missing one does not separate discovery failure from truncation or a response error. So:
(1) each probe runs in a **fresh, isolated session**; (2) the expected sentinel lines are **held by the verifier** and
never shown to the agent; (3) **file and search tools are withheld** during the automatic-loading probe, and any tool
request is recorded; (4) **positive controls** — lines from a file the tool must load — and **negative controls** —
lines from a file it must not load automatically, such as the frozen `docs/PRD.md` — run beside the probe; (5) any
loader or context diagnostic the tool offers is recorded with the result. A specific loader outcome is recorded only
when this evidence separates it; otherwise the result is **`inconclusive`**. A negative control that is quoted
invalidates the run.

*Dated amendment, 2026-09-27 (`D-294`, Judge ruling, option (b) from `B-143`).* **Where the tool offers a loader diagnostic, it decides the loader outcome; the quotations corroborate it.** A loader diagnostic is a harness-recorded injection, for example Claude Code's `attachment:instructions` or Codex's `# AGENTS.md instructions for …` rollout item (control 5).
- **Deciding the outcome.** The diagnostic shows **which** files were delivered, and whether each arrived **complete** (compared byte for byte with the pinned file). That separates complete loading, discovery failure, per-file truncation and total-context truncation.
- **A quote miss on a delivered line.** If a sentinel line is present in the diagnostic but the agent answers it `NOT VISIBLE` or alters it, that is recorded as a **response error**. It is not a loading gap, and it does not by itself make the run `inconclusive`.
- **Unchanged:** the negative control (a quoted negative line invalidates the run), control 3 (any tool call in the probe window makes the run `inconclusive`) and the pin check.
- **Without a diagnostic,** the quotation test alone governs, as written above.

**Run pin and kit isolation (`D-276` items 4–5).** Every run reads the pinned file set below at **`0e33683`**. A
checkout at a later commit is valid only if the SHA-256 of each file in the pinned file set, and of
