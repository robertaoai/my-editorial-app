## 1. GR-013 — Fixture isolation (P2 → P4a)

### 1.1 Problem

`scripts/fixtures/run.mjs` mutates the shared working tree and relies only on a clean-tree refusal at start.
`harness.mjs` calls the `B-021` concurrency lock "unbuilt". All lanes share one checkout, so a second process
(another fixture run, `bun run check`, a graph rebuild, an editor) can read mutated state or write into it. The
`syncDocs()` suite also shows that restore is file-level, not path-baseline-level: it leaves an empty
`.agents/skills/sync-docs/` behind.

### 1.2 Design

1. **Disposable target.** `run.mjs` creates a fresh `git worktree add --detach <tmp> <pinned HEAD>` under the OS
   temp directory, outside the caller's checkout. Every suite runs with that worktree as its root. The caller's
   tracked, index and untracked bytes are never opened for writing.
2. **Pinned inputs.** The pinned revision is the caller's `HEAD`. Inputs the checks read outside Git (for example
   `.graphify/graph.json`) are copied into the target read-only before the first suite. The run records the
   revision and the input hashes in its report.
3. **Same-target refusal.** The target directory is created exclusively (`mkdir` fails if it exists), named per
   run. A second run therefore gets its own target and cannot write into the first. Two runs never share a target.
4. **Baseline-aware restore inside the target.** Each fixture snapshots the paths it will touch (exists? file or
   directory? bytes or entries?). Restore returns each path to its snapshot. A directory the fixture created is
   removed only if all of these hold: it was absent at snapshot, it is now empty, its resolved path is inside the
   target, and it is not a link or reparse point. Otherwise the fixture fails with the path named. **No recursive
   delete.**
5. **Cleanup.** After all suites, the runner removes the worktree with `git worktree remove` and prunes it.
   Ordinary cleanup must succeed. If setup is partial, the run is interrupted, or cleanup fails, the runner exits
   nonzero and prints the task-owned paths left to recover. It never touches the caller's tree to recover.
6. **Clean-tree refusal is retired as the safety boundary.** It may stay as an advisory, since the run no longer
   depends on it.

### 1.3 Files

| File | Change |
|---|---|
| `scripts/fixtures/run.mjs` | Create, pin, run in, and remove the disposable worktree; exit codes as in 1.2 |
| `scripts/fixtures/harness.mjs` | Root-relative paths; path snapshot and baseline restore; containment and link guards |
| `scripts/fixtures/suites.mjs` | `syncDocs()` and any other suite creating directories use the baseline restore |
| `scripts/checks/*.mjs` | Accept an explicit root if any check still resolves paths from the process `cwd` |

Exclusions: no change to `bun run check` semantics, `.github/workflows/` (Lane C) or application code (Lane B).

### 1.4 Definition of done (independently verified)

| # | Case | Pass when |
|---|---|---|
| G13-1 | Ordinary run | All suites report as before; the caller's `git status --porcelain`, index and untracked file hashes are byte-identical before and after |
| G13-2 | Directory absent at start | `.agents/skills/sync-docs/` does not exist in the target after `syncDocs()` |
| G13-3 | Directory already empty | It still exists, empty, after restore |
| G13-4 | Directory holds user content | Content is untouched; the fixture fails if it cannot restore without deleting it |
| G13-5 | Two concurrent runs | Each uses its own target; neither alters the other's or the caller's bytes |
| G13-6 | Reader during a run | `bun run check` in the caller during a run reads unmutated state |
| G13-7 | Interrupted run / failed cleanup | Exit nonzero; leftover paths are named and lie only under the temp target |

Stop condition: any case fails, or the implementation needs to write to the caller's checkout.
